# V3.3 AI REAL · 手动真机 Smoke Test

> 适用分支：`feature/v3.3-ai-real`
> 前置：一台真机（iPhone），一个**真实有效**的 DeepSeek API Key（余额充足）。
> 单测只覆盖映射、迁移、存储与隔离；以下链路必须真机人工验收。

## 准备

1. 从该分支 CI 的 Release / Artifact 安装最新 IPA（TestFlight 或签名直装）。
2. 全新安装（或先在 AI 设置里清除旧 Key），确保拿到干净的配置态。

## 步骤与预期

| # | 操作 | 预期结果 |
|---|------|----------|
| 1 | 打开「小掌柜 → AI 助手 → AI 设置」 | 顶部状态为「未配置」；默认 Base URL 为 `https://api.deepseek.com`；模型为 Picker 且默认选中「DeepSeek Flash（推荐）」，不能自由输入模型名；另一个选项是「DeepSeek V4 Pro」 |
| 2 | 粘贴真实 DeepSeek API Key，点「测试连接」 | 先显示「正在测试连接…」；成功后**仅成功时**显示绿色「连接成功」 |
| 3 | 点「保存」 | 设置页关闭；聊天页头部显示「Key 已保存」（而不是误导性的「已配置/正式版」） |
| 4 | 发送普通聊天：`你好，你是谁？` | 出现真实模型回复（非本地 canned 文案），有正常打字/加载态 |
| 5 | 发送一条**本地 Parser 识别不了**的经营指令，例如：`帮我在系统里记一笔今天晚上八点送到幸福路9号的三杯珍珠奶茶外卖一共45块钱` | 该输入未命中本地 parser 时走远程 LLM tool call；返回可确认的 ActionCard（营业额/待办/备忘/配送类提案），**确认前不写业务库** |
| 6 | 右上角菜单选「清空当前对话」 | 弹出二次确认，标题「清空此对话？」，说明含「只删除聊天记录，不会删除已经保存的营业额、待办、备忘或配送记录。」 |
| 7 | 确认清空 | 聊天消息立即为空；proposals / 未确认 ActionCard 立即消失 |
| 8 | 彻底杀掉 App 进程后重新打开 AI 助手 | 对话仍为空（持久化文件已原子清空，重启不恢复） |
| 9 | 回到业务页面查看 | 此前已确认保存的营业额 / 待办 / 备忘 / 配送记录**一条都不少** |
| 10 | 打开 AI 设置 → 改任意内容 → 点「取消」 | 再次打开设置，改动**未**生效（Draft 被丢弃）；Key 不丢 |
| 11 | 打开 AI 设置 → Key 前后加空格/换行 → 点「保存」 | 再次打开或测试连接正常（保存前已 trim） |

## 异常文案验收（如可复现）

| 场景 | 页面应显示的中文（不得是 NSError/ProviderFailure 英文原文） |
|------|------|
| 错误 Key | API Key 无效 |
| 欠费账户 | 账户余额不足 |
| 模型/参数错误 | API 参数或模型配置错误 |
| 触发限流 | 请求过于频繁，请稍后再试 |
| 服务端 5xx | DeepSeek 服务暂时不可用，请稍后重试 |
| 超时 | 网络请求超时，请检查网络后重试 |
| 无网络 | 当前没有网络连接，请联网后重试 |

## 旧配置迁移验收（升级安装）

- 从旧版本（`deepseek-chat` / `deepseek-reasoner` / 手输的 `DeepSeek`）覆盖安装启动：
  进入 AI 设置应看到模型已自动变为「DeepSeek Flash（推荐）」，请求正常，不再拿旧模型 ID 调用。

## 安全检查

- DEBUG 控制台允许出现：provider id、HTTP status、endpoint host、model id。
- 任何日志中**不得**出现：API Key、Authorization header、完整经营数据。
