## 修复内容

### 1. Snapshot/Widget 刷新合并(trailing-edge 去抖)
- 新组件 `SnapshotRefreshDebouncer`:Repository 每次写成功只"预约"刷新,**250ms 静默窗口内多次写合并为一次**全量快照 + Widget reload + Live Activity 更新;**最后一次成功写入必然最终同步**(trailing edge 永远执行)。
- 防重复触发用"代数对账"(generation counter):被顶替/取消/已落地的旧任务在任何取消时序下都不会再次执行。
- `AppRepository` 全部 26 处单条写路径接入;**批量扫呗导入收尾保持立即刷新**(单次写完,用户马上看 Widget)。
- 立即语义入口不变:`refreshAll`(scenePhase 兜底、GoalEdit、导入)、查询失败保留旧快照(P1-4)。

### 2. App Intent 与 Repository 统一
- `AddTodoIntent` 改为复用 `TodoRepository.add`(原先手写 insert+save+通知+刷新,与 Repository 重复,有口径漂移风险);通知/优先级/截止时间语义完全保留。
- `RecordRevenueIntent` 收入来源按备注派生 `IncomeSource.from(note:)`(与 PR-A 修复后的录入口径一致)。
- 三个 Intent 消除双重刷新:Repository 写后 `flushDebouncedRefresh()` 立即落地(单发场景不等待窗口,App 后台驻留时间短也不会丢同步)。
- `AppDatabase.makeCachedContainer()`:Intent 进程内容器缓存(MainActor),不再每次执行重开 store;构建失败仍走 makeContainer 的全部安全回退与抛错语义。

### 3. 后台切换兜底
- scenePhase `.active/.background` 先落地挂起的合并刷新再走既有全量刷新——切后台瞬间不存在"App 已保存但 Widget 是旧数据"的窗口。
