# 待办 / 日历 / 备忘职责核对（方案，未改业务）

## 当前事实

- TodoTab 为今天/明天/逾期/已完成/备忘。TodoFilter 根据同一 Todo 的 dueDate/isCompleted 过滤；无日期任务也进入今天。首页通过 TodoNavigationState 消费一次 requestedTab 导航到原筛选。
- 日历使用 ScheduleDay 对同一批 Todo/CustomerRequest/Expiry/Memo 做日期投影。待办、日历均通过 TodoRepository.toggleComplete 更新同一模型；不是分别创建任务。日历新建使用 TodoEditorSheet(initialDate: selectedDate)。
- 日历除时间/全天清单外，月历下还有 dayDetail 分类摘要及收支概览；它们可能重复表达数量或标题，但不是重复存储。
- MemoEditorSheet.save 仅调用 MemoRepository.add/update，没有根据文本中的日期创建 Todo。

## A：可随视觉阶段推进的显示优化

1. 待办保留现有五个筛选与导航契约，先统一进度头、时间、优先级及失败重试的信息层级。逾期可通过现有筛选强调，不删除原入口。
2. 日历时间清单只承载有钟点的安排，全天清单承载无钟点的事项；下方分类摘要以汇总/导航为主，减少重复标题。实施前用真实样例和现有 ScheduleDay 测试核对，不改变日期归属。
3. 备忘突出标题、正文、附件与保存时间；不制造执行状态，不在后台复制待办。
4. 各页读取相同对象和完成状态，保持日期变更、编辑、完成后自动刷新。

## B：必须独立评审后才能改变

- 今天/计划/已完成三组替换现有五组：需要定义计划是否包含明天/未来/无日期，逾期如何触达，原备忘入口去向，以及 requestedTab 兼容；当前不实施。
- 备忘转任务：需明确用户点按与确认、原备忘是否保留、如何避免重复转换；当前不新增。
- 模型字段、Repository、提醒调度、持久化迁移：无此授权，不修改。
- 日历彻底删除某类详情或取消已有操作入口：需要先证明功能仍可触达，不以“去重”直接隐藏能力。

本方案不增加数据写入、不变更 SwiftData schema，不把待评审建议当成已批准功能。

## 本轮已实施（不改业务）

- 待办进度与五组筛选保持；失败重试和完成后移至已完成的 UI 回归真实执行。
- 日历今日/选中/月周操作视觉分层，保留有时刻与全天清单、摘要和全部既有入口；不删除信息来制造“去重”。
- 备忘导航标题明确为“备忘记录”，列表时间明确“更新于”，避免与待办执行时间混淆。
- 动态字体日期头只缩放一次；Reduce Motion 新调用点静态呈现。

涉及三组筛选、备忘转任务、提醒或数据归属的方案仍需用户独立决定，本轮没有擅自实施。
