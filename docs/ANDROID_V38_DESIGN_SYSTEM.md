# Android V3.8 Design System 规格

**状态：** Phase 0 设计规格（只读，不含实现）

## 1. 对比表：SleepDown 做法 × 小掌柜现状 × 可借鉴点 × 不可搬用项

> 依据：Phase 0 研究结论（原理转述，无 SleepDown 源码复用）。

### 1.1 设计系统（Design DNA）

| # | SleepDown 做法 | 小掌柜现状（V3.7.1） | 可借鉴点 | 不可直接搬用（原因） |
|---|---|---|---|---|

## 2. V3.8 Design System 规格（基于 V371 演进）

> 演进原则：V371 token（S0–S3、8 字阶、Space/Radius/Shadow、状态色、Light/Dark、Motion 时长档）是地基，V3.8 只做**加法**——新增材质层与 Motion 语言层，不修改已有 token 的语义。

### 2.1 玻璃材质分级（Glass Material Tiers）

**为什么需要分级：** Android 没有 iOS 式的系统级 backdrop blur。在 Android 上实现"玻璃"有三条技术路线，成本与效果差异巨大：

1. **`RenderEffect` 模糊**（API 31+）：可对 View/Compose 节点做真实模糊，但**每帧重建 RenderEffect 开销大**，且不能直接做"采样背后内容"的 backdrop 式模糊——需要手动渲染背景到离屏 Bitmap 再模糊，这是 SleepDown 自研材质管线的核心工作量，小掌柜 V3.8 不做。
2. **静态模糊背景**：预渲染一次背景快照并模糊，适用于背景静止的浮层（如 AI Sheet 展开后背景不动的场景）。
3. **半透明 + hairline 近似**：零 GPU 模糊成本，用半透明底色 + 1dp 高光描边模拟玻璃质感。

**三档定义（独立实现语义）：**

| 档位 | 名称 | 实现语义 | 适用场景 | 降级条件 |
|---|---|---|---|---|
| T1 | 质感 (Fidelity) | 背景静止时：预构建一次模糊快照（10dp plain blur，显隐只改 alpha，不按帧重建）；背景动态时：降为 T2 | AI Sheet（背景为首页静态内容）、确认卡 | API < 31 或低内存设备 → T2 |
| T2 | 性能 (Balanced) | 低采样模糊（RenderEffect 缩放 0.5 后 8dp blur）或静态半透明+双层 hairline；按帧重建禁止超过 16dp 上限 | 弹窗、BottomSheet、Toast 级浮层 | 帧率 < 55fps 持续 1s → T3（运行时自动降级） |
| T3 | 超级性能 (Essential) | **无模糊**：半透明底色（不透明度按"对比度守恒"提高）+ hairline 描边；几何（圆角/层级/间距）与 T1/T2 完全一致 | 低端设备、Reduce Motion 开启、电池省电模式 | 基础档，永不降级 |

**材质声明格式**（每个玻璃表面在设计稿/代码注释中声明）：

```
Material: Glass/T1
Backdrop-Domain: home-feed        # 采样哪个背景域（具名，非自采样）
Role: floating-sheet              # 角色：背景/分组/浮层/决策
Fallback: T2 -> T3                # 显式降级链
```

**对比度守恒规则**（借鉴 6.3）：T1→T2→T3 降级时，底色不透明度必须单调递增，保证同一文字在三档下的对比度落在同一区间。验收时用 Light/Dark 双主题截图 + 对比度计算验证（见 PoC-2）。

**为什么 T3 保留相同几何语义：** 借鉴 1.3——玻璃是附加属性，不是信息载体。用户在低端机上看到的应该是"同样的卡片，只是没那么透"，而不是"布局变了"。这也是无障碍的基本要求（高对比度用户本质上就在用 T3）。

### 2.2 Droplet Morph 动作分层（小掌柜 Motion 语言）

> 不复制 SleepDown 的 260ms/2.2%/3.5% 数值；分层思想吸收，数值用 V371 时长档重新标定。

**适用对象：** 从一个可见锚点控件膨胀/收缩的浮层——V3.8 首批只有两处：首页 AICommandEntry → AI Sheet、待办 QuickAction 菜单（见 PoC-1）。其他弹窗一律走标准淡入+上浮，不许滥用液滴。

**六层动作（按相位顺序）：**

```
Phase A  锚点确认 (0ms)
         └─ 必须存在可见的出发控件；无锚点 → 降级为标准淡入（具名原因：no-anchor）

Phase B  收缩 ⊗ 位移同起
         └─ 锚点控件轻微收缩（scale → 0.96，按 PRESS_SCALE 语义）与浮层位移
             同时启动；禁止"先收缩完再位移"（会产生第二个零速度起点，体感卡顿）

Phase C  高度先行展开
         └─ 浮层先纵向展开到目标高度的 ~90%，再横向补足宽度；
             纵向用 STANDARD 档（280ms），横向滞后约 1/4 相位

Phase D  圆角延迟插值
         └─ 圆角从锚点控件的圆角向目标圆角插值，延迟 Phase C 约 1/3；
             运动方向前缘允许轻微锥度（不对称圆角），稳定态必须回到标准圆角 token

Phase E  内容延迟显现
         └─ 内容 alpha 在几何展开进度 1/4 → 3/4 区间淡入；
             禁止内容先出现再展开（"空壳先飞"是廉价感的主要来源）

Phase F  末段一次过冲 + 锚点回归 + 释放
         └─ 展开末段允许一次轻微过冲（幅度 < 3%，仅一次）；
             收起时反向执行各相位，最终回到锚点控件；
             动画结束后释放所有临时形变（scale/圆角/裁切回到 token 标准值）
```

**反例清单（出现即视为实现不合格）：**
- 收缩播完才开始位移（双零速度起点）
- 内容在几何展开前出现
- 过冲超过一次或幅度肉眼可辨的"果冻感"
- 动画结束后圆角/阴影停留在中间值
- 无锚点控件却强行做液滴展开

### 2.3 MotionSpec / MotionPolicy

**MotionSpec**（每个转场/动效的声明，代码注释 + 设计稿标注）：

```
MotionSpec {
  transitionKind: NATIVE | FADE | SHARED_ANCHOR
    # NATIVE=平台默认（Compose 默认转场）；FADE=淡入淡出+轻微位移；
    # SHARED_ANCHOR=液滴式锚点展开（仅 §2.2 批准的场景）
  durationTier: INSTANT(100) | FAST(180) | STANDARD(280) | EMPHASIZED(420)
    # 沿用 V371Motion 时长档，不新增数值
  interruptible: true   # 中途反转是否保持速度续播（默认 true）
  overshoot: NONE | CONTENT_ONLY
    # 页面容器永远 NONE；内容分组允许 CONTENT_ONLY（"内容可过冲、页面必单调"）
}
```

**transitionKind 选择规则：**
- Tab 切换 / 页面导航：`FADE`（页面容器单调 tween，内容分组错峰淡入）
- 浮层/弹窗：`FADE`（特殊批准的两个场景用 `SHARED_ANCHOR`）
- `NATIVE` 仅用于系统级交互（返回手势跟手），不用于页面间转场——**为什么：** NATIVE 在不同 OEM 上表现不一致，OPPO ColorOS 的 Activity 转场与 Compose NavHost 转场混用会产生撕裂；FADE 是可预测、可测试、可降级的最小公分母。

**MotionPolicy**（运行时策略，含降级链）：

```
resolve(surface, deviceCapability, reduceMotion) -> ResolvedMotion
  1. reduceMotion == true
     → 全部退化为 FAST 档短淡入（≤180ms），无位移、无弹簧、无过冲、无模糊
     → 具名原因：reduce-motion
  2. deviceCapability.perfTier == ESSENTIAL
     → 禁用 SHARED_ANCHOR（→FADE）、禁用 T1/T2 材质（→T3）、禁用运动模糊
     → 具名原因：perf-tier-essential
  3. 密集列表（可见卡片 > 10）
     → 内容错峰退化为整面单调滑动
     → 具名原因：dense-list
  4. 能力探测失败（如 RenderEffect 不可用）
     → 返回具名失败原因（例：render-effect-unsupported-api-29），走声明的 fallback
```

**能力探测返回具名失败原因**（借鉴 5.1）：`probeGlassCapability()` / `probeTransitionCapability()` 不返回 Boolean，返回 `CapabilityResult.Ok` 或 `CapabilityResult.Unsupported(reason: String)`。reason 必须是可以写入日志和 PoC 报告的具名词（如 `no-backdrop-blur-on-api-29`），禁止裸 `false`。

**性能降级策略：**
- 运行时帧率采样：连续 1s < 55fps → 自动降一档（T1→T2→T3；SHARED_ANCHOR→FADE），并记录降级事件（不记业务正文，只记档位变化）。
- 降级是单向的（只降不升），避免档位抖动；回到前台时重新探测。
- 每个动效/材质的降级路径必须在 MotionSpec 中预先声明，**无声明的动效不允许合入**（回退开关要求，见 Roadmap §2）。

## 3. 四页面升级提案

> 每个升级点 = 一个具体交互/视觉变更 + 为什么 + 怎么验。**不是换肤**：不改信息架构、不改 Room schema、不改 AI 执行链。

### 3.1 首页（Home）——AICommandEntry → AI Sheet 的液滴展开

- **升级点：** 首页底部 AI 输入入口点击后，AI Sheet 从入口控件位置做液滴式展开（SHARED_ANCHOR，§2.2 六层动作）；收起时反向回到入口。
- **为什么：** 当前 AI Sheet 是 Root 级 ModalBottomSheet，与入口控件无视觉关联，用户感知是"凭空出现"。锚点展开建立"入口→Sheet"的因果链，符合"运动有来处"原则；同时这是 Droplet Morph 语言的第一个生产落点，验证整套分层规则。
- **验收标准：**
  1. 录屏逐帧检查：Phase B–F 顺序正确，无"收缩播完才位移"、无"内容先出现"；
  2. Light/Dark 各 1 张展开中途截图 + 1 张稳定态截图，稳定态几何与现有 Sheet 一致；
  3. Reduce Motion 开启时退化为 FAST 短淡入（录屏验证）；
  4. 低端档（T3/ESSENTIAL）下为 FADE 无液滴（具名降级日志可查）。

### 3.2 待办（Todo）——勾选的触感 + 状态动画

- **升级点：** 待办勾选/取消勾选：① 按压瞬间触感反馈（Haptic，V371 唯一定义点）；② 勾选框 ✓ 绘制动画（FAST 180ms，打钩路径动画）；③ 行内文字同步变为"已完成"样式（删除线淡入，非瞬切）；④ 取消勾选反向播放。
- **为什么：** 勾选是待办页最高频操作，当前是瞬切+无反馈。触感+绘制动画把"状态变更"从"值变化"升级为"被确认的动作"，减少用户重复点击的不确定感；同时与 V3.7.1 验收修复轮的 ScheduleTimelineRow 图标口径统一（完成=实心态、未完成=空心态），动画只表达过渡，不改变图标语义。
- **验收标准：**
  1. 勾选/取消各 10 次，触感每次触发（真机 NOT RUN 项除外，模拟器用日志断言）；
  2. 慢放录屏确认打钩路径动画完整播放、无跳帧；
  3. 与日历/首页任务行的完成态图标语义一致（截图三处并排对比）；
  4. Reduce Motion 下：无绘制动画，直接切换终态（仍保留触感——触感不是视觉动效，不降级）。

### 3.3 日历（Calendar）——周切换的双轨运动

- **升级点：** 日历周视图左右切换：页面容器周做单调滑动（无过冲），日期格内容做分组错峰淡入（每组延迟 18ms 量级，按小掌柜时长档标定）；连续快速滑动时中途反转保持速度续播。
- **为什么：** 周切换是日历页最高频手势。单调滑动保证"页面必单调"（可预测、不晕），内容错峰让日期格有"跟上来"的层次感而不喧宾夺主；可中断续播解决快速连滑时的"动画排队卡顿"——这是当前瞬切方案在加入动画后最可能引入的新问题，提前用规则堵住。
- **验收标准：**
  1. 慢/快两种速度滑动录屏：容器轨无过冲（逐帧位移单调），内容轨有可见错峰；
  2. 快速连滑 5 次无动画堆积、无卡顿（帧率 ≥55fps，PoC 帧率数据）；
  3. 中途反向滑动时速度连续（无"急停再起"）；
  4. 标题「日程」vs Tab「日历」的不一致随本次一并收敛（归属 V3.7.1 验收修复轮口径，V3.8 合并时确认）。

### 3.4 经营（Business）——数字的 Motion 呈现

- **升级点：** 经营页核心数字（今日营收/本月营收等）：① 数字变化时做滚动递增/递减动画（STANDARD 280ms，numeric 语义）；② 数字颜色按涨跌语义只用状态色（涨/跌各一套，不混用正文色体系）；③ 首次进入页面时数字从 0 滚动到实际值（仅首次进入，非每次可见）。
- **为什么：** 经营页是"钱"页，数字是核心信息。滚动呈现让"变化"本身可见（用户能感知到"涨了多少"的过程，而不仅是结果）；"首次进入才滚动"避免每次切 Tab 都重播造成的廉价感；颜色成套呼应设计 DNA 1.4。
- **验收标准：**
  1. 数字从 0→目标值滚动过程录屏，时长落在 STANDARD 档 ±20% 内；
  2. 涨/跌/持平三种状态截图，颜色分别唯一对应状态色（取色验证）；
  3. 二次进入页面无重播（录屏验证）；
  4. Reduce Motion 下直接显示终值（numeric→终值，符合 V371Motion.resolve 既有语义）。

## 4. 设计评审检查表（Checklist）

- [ ] 锚点：SHARED_ANCHOR 有可见出发控件；无锚点已降级为 FADE（具名原因）
